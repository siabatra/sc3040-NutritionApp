MealCare app reference

Dashboard: shows today's logged calories/macronutrients, targets, recent meals and saved meal plan. Use Log Meal to record food, Plan My Day for planning, Find Restaurants for discovery, View Full Analytics for analytics, and View All or History for meal history. Settings opens profile and preferences.

Meal logging: choose meal type and date and enter the food or meal name. The USDA Food API lookup retrieves and automatically fills calories, protein, carbohydrates and fat, so users do not need to enter those nutrients manually when lookup succeeds. Review the retrieved values and save the meal. Manual nutrient entry is available if lookup cannot find the food or the user needs to correct the values. A recorded meal contributes to intake. Edit or delete saved meals from Meal History; filters support dates and meal types.

Plan My Day: choose home or restaurant meals and dietary preferences, generate a plan, and save generated plans. Manual Add planned meal allows entering a dish and nutrition without AI generation; Add and save planned meal saves it for today immediately. A planned meal is not recorded intake: log it separately when eaten, ideally from the saved plan so it links correctly. Existing meal generation uses a separate provider and can fail if its API balance is insufficient; manual planning remains available.

Dining Analytics: Daily, Weekly, Monthly and Yearly periods with historical selection. Shows logged nutrition averages/trends, planned versus recorded calories/macros, macronutrient gaps, recorded minus planned calories, confirmed meal plan adherence and adherence trends, macro distribution, meal counts, calories by meal type, restaurant/home/custom distribution and insights. Saved plans are the comparison baseline; calorie targets are a different baseline. Positive recorded-minus-planned values mean excess and negative values mean shortfall. Confirmed adherence matches same-day planned/logged dish and nutrition, with each meal counted once. Log from your saved plan for reliable linking. One entry can be displayed; more entries improve trend reliability. Missing plans prevent plan comparisons, while recorded nutrition remains available. No recorded meals means no recorded intake. Check the selected date/period if a meal seems missing.

Analytics uses Asia/Singapore dates, Monday-start weeks, calendar months and years. Summaries are computed by the backend and the dashboard subscribes to changes. Local npm run dev starts the analytics worker; processing can take a moment. Last updated shows summary freshness. Production background updates require backend deployment. Historical edits/deletions are reflected when summaries rebuild. Retry is available for failed loading.

Restaurants: find nearby restaurants, view dishes and provided nutrition, save favorites and view directions/maps. Settings supports profile, daily calorie target/preferences and theme. Account access requires sign-in. This chatbot explains features only; it cannot inspect your personal meals, account, summaries or location, change preferences, save meals, or diagnose a specific account's backend state. It uses OpenAI and sends chat messages to OpenAI through an authenticated server. Chat is kept in memory and cleared when you sign out or choose Clear.

Settings: Profile Information has Edit controls; update the relevant information and save changes. Age, sex, height, weight, activity level and goal type influence the computed daily calorie target. A confirmation may show the new target before saving. Sign Out is in Settings. Account registration and sign-in use email/password. Forgotten-password recovery includes email verification and a new-password form; passwords must match and have at least six characters. Email verification/recovery needs the existing email backend running and configured. No reference-backed account deletion feature is available.
