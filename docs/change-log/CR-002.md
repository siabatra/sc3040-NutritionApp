### 1 · Generate: what is requested, and why
Add **Delete Account** and **Account Recovery** as **use cases 18 and 19**.

These are required to meet the retention and deletion obligations in **Section 6.5 of the SRS**, and support risk **R5 (PDPA non-compliance)**.

### 3 · Evaluate: impact
- **Scope / product:** two new use cases.
- **Security and privacy:**
  - users can permanently erase their data
  - deletion and password reset must be protected against misuse: deletion requires the user's password, and recovery requires an emailed one-time code
- **Documents to update:** SRS use case table (use cases 18 and 19) and sequence diagrams.

### 5 · Implement
**Use case 18: Delete Account.** Commit `a75236f`, "Add delete account feature" (22 Oct 2026).
- `project/utils/accountDeletion.ts`:
  - re-authenticates with the user's password before anything is removed
  - deletes the profile (`users/{uid}`), all meal plans (`users/{uid}/plans`) and all meal logs (`mealLogs` where `userId` matches), in batches of 400
  - then deletes the Firebase Auth account
- The existing backend triggers (`removeProfileAnalytics`, `removeDeletedAccountAnalytics`) clear the derived analytics.
- `project/app/(app)/settings.tsx`: a Delete Account button below Sign Out, with a password confirmation dialog and clear error messages.
- `project/server/app-help.md`: the help assistant explains how to delete an account.
- Test (Firestore emulator), "account deletion removes only the owner profile, plans and meal logs", in `project/functions/test/firestore.rules.test.cjs`:
  - deletes 450 meal logs
  - leaves another user's data intact
  - confirms one user cannot delete another user's data

**Use case 19: Account Recovery.** Forgot-password flow:
- `forgot-password.tsx` → `otp-verification.tsx` → `password-reset.tsx`
- backed by the email server's `/send-otp`, `/verify-otp` and `/reset-password` routes in `project/server/server.js`
